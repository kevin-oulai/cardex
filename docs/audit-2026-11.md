# Audit — 12 November 2026

## Backend fixes (applied to the live project, source in `backend/2026-11-audit-fixes.sql`)
| Severity | Problem | Fix |
| --- | --- | --- |
| High | `cardex_recycle_duplicates` rejected every `car_id > 95` (catalog had 192) — per-model recycling failed for half the cars | Validate against `vehicle_catalog` |
| High | A duplicate listed on the market made the market guard trigger abort the **whole** recycle batch | Listed and Showdown-referenced cards are excluded; the kept copy is chosen to be a non-listed one |
| High | `profiles` was fully updatable by its owner: `equipped_title` could be set directly, bypassing unlock checks | Column-level grant: only `display_name` is client-writable; whitespace-only names rejected for new writes |
| Medium | JDM pool has no Legendary+ cars, so pity never reset there and every JDM pack after #59 silently forced the top tier | A forced draw now consumes pity |
| Medium | Public profiles always showed a hard-coded avatar, bio and "top 3 by rarity" — the avatar/bio/theme/showroom players set were never visible to anyone | `cardex_public_collector` returns sanitised avatar/bio/theme and the chosen showroom (ownership-checked) |
| Low | Notifications had no actor name ("sent you a friend request" — from whom?) | `actor_name` added to `cardex_social_list` |
| Low | Legacy single-item RPCs `cardex_open_pack` / `cardex_buy_ticket` were still client-callable | Execute revoked; batch RPCs remain the only entry points |

## Frontend defects removed by the rewrite
- Inventory capped at 1,000 cards (PostgREST max rows) despite `.limit(10000)` → paginated.
- Preference saves embedded the whole inventory → hit the 64 KB RPC limit around ~500 cards.
- Every page load fired 16 uncached Wikipedia requests → 4 batched requests, cached for 7 days.
- Clicking a notification never marked it read (selector looked for an attribute that was never rendered).
- Market called the currency "coins", everything else "credits".
- Profile claimed the showroom/wishlist were "saved on this device and included in save exports" (exports were retired).
- `photoTitles` table out of sync with the catalog (logged an error on every load).
- Garage "favorites" button on cards was labelled "Garage" when active.
- No password-reset flow.
- Seven HTML fragments + four scripts loaded serially before anything rendered.

## Catalog de-duplication (`backend/2026-11-catalog-dedup.sql`, applied)
18 cars were listed twice with conflicting rarity or stats (Enzo, LaFerrari, Zonda F, Countach, Carrera GT, XJ220, Giulia QV, Elise S1, Exige, DBS V12, P1,
911 Turbo 930, 190E Evo II, MR2 SW20, Integra DC2, 3000GT, 300ZX, Civic Type R FK8). The catalog is now 174 unique cars with ids 0..173; car ids are enforced
by foreign keys. All game progress was reset (test accounts only); accounts, profiles and friendships were kept.
